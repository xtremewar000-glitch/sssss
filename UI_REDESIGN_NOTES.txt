VPK Tool v11 - UI refresh
========================

This package refreshes the desktop shell and the Models (WPK) editor layout.
The work is limited to presentation and navigation; WPK/VPK parsing, import,
export, rendering, copy-to-kit, texture handling, and save callbacks are retained.

Main workspace
--------------
- Left-side workspace navigation and grouped pages.
- Consistent dark workshop theme for the main application shell.
- Existing pages retained: Stickers, Vehicle Models, Backfire, Wheels, Lamps,
  Meters, and Engine Sound.

Models (WPK) editor
-------------------
- Compact car / aero-kit selector and WPK open action.
- Source folders consolidated into one horizontal locations panel.
- Part inventory separated from the 3D preview.
- Part actions grouped together: export, replace, add, move tag, copy to kits,
  delete, visibility, and undo.
- Model utilities grouped separately: textures, shadow, gloss, lights, windows,
  arcade import, FBX conversion, livery, paint colours, and arcade rebuild.
- Preview controls grouped beneath the preview.
- Save, Save As, and Bake AO remain in the footer.

Validation
----------
- All Python modules pass py_compile.
- Models (WPK) tab instantiates under Tk/Xvfb.
- A sample WPK opens and populates the part inventory and preview.
- No game data or binary formats are modified by this UI-only update.

Notes
-----
The redesign preserves the existing editor functions and callbacks. It does not
add new model conversion or game compatibility features.

FBX import workflow
-------------------
- The FBX replace dialog now shows a detected-part inventory with mesh counts
  before import (body, wheels, wing variants, and bonnet variants).
- Source variant selection is presented separately and lists only aero kits
  detected in the FBX.
- Whole-car replacement now asks for confirmation and summarizes the source
  variant and detected parts before changing the open WPK.
- Clearing the destination car's old lamps, mirrors, wing, and bonnet options
  is now opt-in rather than enabled by default.
- Selected-part import checks that the FBX actually contains that part before
  beginning the replacement.

Validation for this pass

- A sample WPK opens and loads its part inventory under Xvfb.

Milestone 4 - Asset Browser + interactive viewport + Properties + operation log
================================================================================
New file: wpk_browser.py (pure Python/numpy, no Tk). Changed: wpk_edit.py (Models tab layout + new methods only).
New: tests/ (synth.py, faketk.py, test_browser.py, test_ui_faketk.py).  Run:  python tests/test_browser.py  and  python tests/test_ui_faketk.py

User-visible
- Models tab is three resizable columns: ASSET BROWSER | 3D VIEWPORT | PROPERTIES (+ Model tools), with an OPERATION LOG strip below.
- Asset browser: grouped tree (Body / Wheels / Wing / Bonnet / Lights / Mirrors / Exhaust / Other), search by name, tag (0x122 or 290,
  every word must match) or texture name, category chips, per-part visibility dot (click it), draws + triangle counts, multi-select,
  group header selects its parts, empty states for "no WPK" / "no match".
- Viewport: drag = orbit (switches to the Free view), right-drag or Shift-drag = pan, wheel = zoom, double-click / "Fit / reset camera" = fit.
  Click a part = select it (Ctrl/Shift = add/remove); the browser follows and clears any filter that would hide it.  The selected part is
  tinted + outlined from the last picture's per-pixel part map (no re-render).  Fixed views (Front 3/4 ... Top) still work and reset the framing.
  While the mouse moves the picture is drawn at half size, then redrawn full size; stale pictures are cancelled.
- Properties (read-only except visibility): name, tag/hex, category, "not drawn by the game engine" flag, draws / vertices / triangles,
  size + centre (model units), material rows (texture, blend, triangles), texture references with size, format and status
  (ok / borrowed (stock pack) / MISSING).
- Operation log: info / success / warning / error lines with time, progress bar for the picture being drawn, error detail text
  (tracebacks for draw failures), Copy all / Clear / Hide.  Logged: open, save (+ .bak), Copy to kits per destination file and
  partial failures, move-tag refusal, Bake AO, draw errors.

Preserved (not edited): Pack/Chunk/Batch, serialisation, tag assignment, copy_parts, move_part, replace/import code, textures, save/.bak.
All existing buttons keep their callbacks; Part actions and Model tools moved to the left / right columns (2-column grids).
Behaviour differences to know about:
- The preview is now always framed from the parts' bounding boxes (needed so pan/zoom are consistent); the default framing can
  differ a little from before.
- "Show / hide" now redraws without re-decoding textures (render(reuse=True)); every edit still rebuilds the model.
- After Add part the new row is selected through select_tag(), which clears a search/filter that would hide it.

Validation done (sandbox without Tk)
- py_compile of every module; pyright finds no undefined names in the Tab class.
- tests/test_browser.py (12 tests): categories, rows, search/filter, camera maths, picking against the REAL rasterizer's per-pixel batch
  map on a synthetic WPK3 written and re-read through wpk_edit.Pack, overlay, part info, log; load -> to_bytes is byte-identical.
- tests/test_ui_faketk.py (13 tests): the REAL Tab code driven through a fake tkinter: empty states, open, browser population, search/chips,
  browser->props/overlay, viewport pick->browser (incl. through a filter), visibility is preview-only and leaves the WPK bytes unchanged,
  orbit/pan/zoom/fit, kit switch, delete/undo, Save As byte-identical, open-error and draw-error logging.

NOT validated
- Nothing was run in real Tk: layout, sash sizes, fonts, colours, focus/tab order, mouse feel and performance are unverified.
  No screenshot of the running application exists yet.
- No real car WPK, FBX or OBJ, and no multi-kit car with real wing/bonnet options was available.
- Existing flows (Export OBJ, Replace OBJ, Add part, Move tag dialog, Copy to kits dialog, textures, gloss, FBX import/preview,
  livery) were not re-run end to end; their code is unchanged apart from the log calls listed above.

Known limitations
- No wireframe mode or grid/axes (the software rasteriser has no wireframe path).
- Glass / see-through batches are drawn but not pickable (they are not written to the pick map).
- Hidden parts cannot be picked or highlighted; the Properties panel still shows them.
- Part name, tag, materials and textures are shown read-only: the only editing paths remain the existing dialogs.
- Position/offset is shown as the bounding box centre; import/source information is not stored in a WPK, so it is not shown.
- No thumbnails, no Redo, no layout persistence (Milestone 6).

Real-file validation (added after Milestone 4 coding; still NOT run in real Tk)

  carss2.zip is not a readable ZIP (bad header) and was not used.

  full frame 0.18 s and half-size orbit frame 0.07 s at 640x360 (software rasteriser, this sandbox's CPU), click-pick returns the

Milestone 5 - Textures and materials window
===========================================
New file: wpk_texmgr.py (pure Python/numpy/PIL, no Tk; only READS a Pack).  Changed: wpk_edit.py (the Textures window, a few hooks).
New tests: tests/test_texmgr.py, tests/test_ui_texdlg.py, tests/regress_ops.py.

User-visible (Models tab > Textures...; also double-click a texture in the Properties panel)
- One window instead of the plain list: search (name, size such as 256x256, format such as 565, status, part name or tag such as 0x122),
  quick filter (All / In use / Unused / Borrowed / Missing / Paint copies / Problems), counts line (unused / borrowed / problems).
- Per texture: size, format (RGB565 / RGBA4444 / RGBA5551), status (ok / borrowed from the stock pack / MISSING / BAD DATA, plus
  unused, paint copy, orphan paint copy, duplicate name, odd size) and which parts draw it and how (picture / reflection / specular).
- Preview decoded on demand (never all at once), cached (LRU, keyed by a checksum of the data so an edit can never show a stale picture),
  on a checkerboard / dark / light background so transparency is visible.  A borrowed texture previews from the stock pack.
- "Select parts in browser" selects the parts that draw the chosen texture(s).  "Report..." lists every problem and copies it.
- Replace from picture...: replaces exactly the selected slot (same name; no typing).  It asks first, with the facts, when the texture is
  shared (several parts, used as reflection/specular map, has paint copies p1..p5, or Aero kits beside the file borrow it) or when the
  picture would lose transparency; it shows the size/format it will be written as.  Simple unshared replaces just happen.
- Add new from picture...: as before, but a name that differs from an existing one only by extension asks first (it would be a SEPARATE
  texture that no part uses).  The default name is no longer the selected texture's name.
- Delete...: as before, plus the paint-copy and aero-kit warnings.  Export PNG... as before, errors are reported instead of raised.
- Every change snapshots first (Undo works), logs to the operation log, and marks the document modified.  Nothing is saved until Save.
- The window follows undo, open and kit switches.

Behaviour difference worth knowing
- The old Textures list called the paint copies (p1:..p5:name) "(unused)" and the delete prompt said "Nothing uses them".  The game picks
  them by name, so they are now shown as "paint copy" and never as unused.  On the 105 real cars supplied: 1610 textures, 344 of them paint copies.

Reused, not changed: Pack.add_texture, Pack.delete_textures, Pack.save (+ .bak), decode_tex, encode16, kit_files, stock_pack_of.
Not added: editing material assignments (a draw's texture / blend / shader).  Materials are listed read-only (Properties panel and the
"used by" list).  No new texture formats: only what encode16 / decode16 already handle.

Validation (this sandbox has no tkinter, so nothing ran in real Tk)
- py_compile of every module.  tests/test_browser.py 12, tests/test_ui_faketk.py 13, tests/test_texmgr.py 17 (11 synthetic + 6 on real cars,
  set VPK_REAL_CARS=<folder>), tests/test_ui_texdlg.py 13 (the real dialog code through a fake tkinter).

  and 13 semantic checks pass (round-trip triangle counts, copied wing arrives, .bak is the original, untouched files unchanged).
- Real data: all 105 readable WPKs give a clean texture catalogue (0 dangling references, 0 missing, 0 unused); every texture of the first 40
  cars previews; kit_borrowers finds Aero A/B/C on the real stock pack.

NOT validated
- Real Tk: layout, fonts, colours, pane sizes, focus / tab order, how the preview looks and feels.  No screenshot of the running app exists.
- Real FBX/OBJ from a representative vehicle (the round trips use this tool's own exports) - import validation of a third-party model is pending.

Milestone 6 follow-up: unified states + Linux maximised window
--------------------------------------------------------------
- vpk_ui.StatusLine replaces the plain text status variable on EVERY page (Stickers, Models footer, Backfire, Wheels, Lamps, Meters, Engine).
  It keeps the old .set(text) / .get() calls working and adds an optional level: set(text, "error").  Six states, one look everywhere:
  empty (muted, nothing open yet), loading (blue, "◌" + a small busy bar), info, success (green "✔"), warning (orange "⚠"), error (red "✖").

  as a last resort) and remembered; restoring uses vpk_ui.set_maximised (state("zoomed"), else attributes("-zoomed")).  The UV "big window"

- Tests: tests/test_status_states.py (13).  All earlier suites still pass (test_ui_m6 21, test_ui_faketk 13, test_ui_texdlg 13, test_browser 12, test_texmgr 17).

Car preview window on small screens
-----------------------------------
The Car panel (Paint, Texture, Aero kit, Wing ... Wheels = 11 combo boxes) was one tall column, so on a 1360 x 768 screen the controls took
about 2/3 of the window and the picture shrank to ~200 px.  It is now two columns (6 + 5 rows) and gets a wider share of the window
(panel widths 5 : 4 : 4), which gives the picture back roughly 160 px of height.  Not run in real Tk: check the combo boxes are wide enough.

Models viewport: steady camera
------------------------------
The framing was recomputed from the car's PROJECTED bounding box at every redraw, so the car's centre and size changed with the angle: the
car drifted and "breathed" while dragged.  wpk_browser.view_extent now fits the car's bounding SPHERE (all parts, hidden ones included,
92% of the radius): the centre stays at the picture centre and the scale is the same from every angle, so orbiting only turns the car.
Test: test_browser.test_fit_does_not_move_while_orbiting.  Side effect: a side-on car is ~10% smaller than before (zoom with the wheel).
Not run in real Tk / on a real car; mouse feel unverified.

Models viewport: live dragging + 360 degree orbit
-------------------------------------------------
Why it only moved on release: every mouse move started a NEW picture and cancelled the one being drawn, so while dragging no picture ever
finished (the drawing takes longer than the gap between two mouse events); the result was polled only every 80 ms as well.
Now: one picture is drawn at a time and a drag keeps only the NEWEST camera; the moment a frame is done the next one starts from the current
mouse position (pump polls every 10 ms while drawing).  Drag frames skip the pick map / selection outline and swap the picture in place
(no clear + redraw flicker); the drag resolution adapts to the speed (1/1 .. 1/5 size, aiming at ~30 pictures a second), and the sharp
full-size picture (with the selection outline) follows 220 ms after the mouse rests.
Camera: orbit is a full 360 degrees on both axes (no stop at the poles); upside down, a drag to the right still turns the car to the right.
Tests: test_ui_faketk 07b (a drag never cancels the frame in flight, newest camera drawn next, pick map kept) and 07c (over the top).
Measured on the synthetic car only (900x500 77 ms, 450x250 18 ms, 300x167 9 ms per frame); a real 18k-triangle car and the real Tk feel are NOT measured.

Wheel over a viewport no longer scrolls anything else
-----------------------------------------------------
Two global wheel handlers (bind_all) also fired for a wheel turned over a picture, so a scroll bar moved while zooming.
The viewport wheel handlers (Models viewport, Car preview, UV big window) now return "break", which stops Tk passing the event on, and the
Textures / materials table's wheel handler only scrolls while the pointer is over that table.  Not run in real Tk.

GPU viewport on macOS: off-screen mode
--------------------------------------
gl_viewport.mode() picks "direct" (pyopengltk frame; Windows / Linux) or "offscreen" (macOS, or pyopengltk missing, or VPK_GL_MODE=offscreen).
OffscreenGLViewport = the same Renderer drawing into a standalone moderngl context's framebuffer; each frame is read back, flipped and
shown on a Tk canvas (PhotoImage.paste when the size is unchanged).  Same interface as GLViewport, so wpk_edit only calls
GLV.create_viewport(...).  requirements-gpu.txt skips pyopengltk on macOS; build_mac.sh bundles moderngl / glcontext.
Tests: tests/test_gl_offscreen.py (8, fake GL).  NOT run: real OpenGL, a real Mac, Retina sharpness, PyInstaller bundling of glcontext.
